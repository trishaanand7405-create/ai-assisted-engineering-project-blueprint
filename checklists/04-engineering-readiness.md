# Engineering Readiness Checklist

> **Engineering work should begin with a sufficiently understood technical path, appropriate tooling and a clear definition of completion.**

Use this checklist before starting significant implementation work.

---

## 1. Repository and Project Structure

* [ ] The source-code repository exists.
* [ ] The project structure is understood.
* [ ] Required directories and files are established.
* [ ] Version control is functioning correctly.
* [ ] The team understands the branching or collaboration approach.
* [ ] Important project documentation is available.

---

## 2. Development Environment

* [ ] Required operating-system assumptions are understood.
* [ ] Required language/runtime version is identified.
* [ ] Required development tools are available.
* [ ] Dependencies can be installed.
* [ ] The application can be run locally.
* [ ] Basic environment setup is documented.
* [ ] Team members can reproduce the development environment.

---

## 3. Solution Design

* [ ] The intended solution is understood.
* [ ] Major components are identified.
* [ ] Important interfaces are understood.
* [ ] Data flow is sufficiently clear.
* [ ] Important architectural decisions are documented.
* [ ] Known technical constraints are visible.
* [ ] Unnecessary complexity has been avoided.

---

## 4. Implementation Readiness

* [ ] The implementation task is clearly understood.
* [ ] Required inputs are available.
* [ ] Expected outputs are defined.
* [ ] Dependencies are identified.
* [ ] Acceptance Criteria are understood.
* [ ] Testing expectations are known.
* [ ] Documentation requirements are understood.

---

## 5. Code Quality

* [ ] Coding conventions are understood.
* [ ] Naming conventions are clear.
* [ ] Error handling expectations are understood.
* [ ] Logging requirements are known where applicable.
* [ ] Security considerations have been identified.
* [ ] Code should remain understandable to another team member.
* [ ] Unnecessary duplication is avoided.

---

## 6. Testing Readiness

* [ ] Appropriate test types are identified.
* [ ] Unit testing requirements are understood.
* [ ] Integration testing requirements are understood where relevant.
* [ ] Acceptance testing expectations are understood.
* [ ] Test data or fixtures are available where needed.
* [ ] Tests can be executed locally.
* [ ] Expected evidence of completion is understood.

---

## 7. AI-Assisted Engineering

* [ ] Appropriate AI-assisted activities have been identified.
* [ ] AI-generated code will be reviewed before acceptance.
* [ ] AI-generated dependencies will be evaluated.
* [ ] AI-generated tests will be checked for meaningful coverage.
* [ ] Sensitive information will not be unnecessarily shared.
* [ ] AI-generated explanations will be verified.
* [ ] Human ownership of engineering decisions is maintained.

---

## 8. Integration and Dependencies

* [ ] External dependencies are identified.
* [ ] Required interfaces are available.
* [ ] Version compatibility is understood.
* [ ] Integration assumptions are visible.
* [ ] Failure behaviour is considered.
* [ ] Dependency risks are understood.

---

## 9. Completion Readiness

Before implementation begins, the team should be able to answer:

* [ ] What are we implementing?
* [ ] Why are we implementing it?
* [ ] How should it work?
* [ ] What components will change?
* [ ] How will we test it?
* [ ] What does "Done" mean?
* [ ] What evidence will demonstrate completion?

---

## Engineering Decision

### Ready

The technical work is sufficiently understood to begin implementation.

### Not Ready

Important technical uncertainty remains.

Resolve or explicitly manage the most significant uncertainty before committing substantial implementation effort.

---

## Guiding Principle

> **Understand the problem, establish the technical path, define completion and then implement with evidence.**
