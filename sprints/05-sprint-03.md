# Sprint 3 — Solution Design

> **Turn the highest-value product requirement into a buildable technical solution.**

Sprint 3 connects the Product Backlog with Engineering.

The team selects a meaningful backlog item and determines **how it can be implemented**.

---

## Sprint Goal

> **Create a simple, understandable and testable solution design for the first valuable product increment.**

---

## Inputs

Bring forward:

* Product Vision
* Product Goals
* Prioritised Product Backlog
* Highest-priority User Story
* Acceptance Criteria
* Project Track

The team should not redesign the entire product.

Focus on the **next valuable increment**.

---

## 00–10 min — Plan

The team should:

* Select the Sprint Goal.
* Confirm the User Story.
* Review Acceptance Criteria.
* Identify the expected inputs and outputs.
* Identify important constraints and dependencies.

Ask:

> **What is the smallest useful version we can build?**

---

## 10–45 min — Execute

Create a lightweight Solution Design.

### 1. Identify Components

Determine the major components required.

Depending on the project:

* Data source
* Processing
* Model
* API
* Application
* Dashboard
* Agent
* Simulation
* Storage

### 2. Define the Flow

Create a simple system/data flow:

``
INPUT
  ↓
PROCESS
  ↓
COMPUTE / MODEL / LOGIC
  ↓
OUTPUT
  ↓
USER
```

Adapt the flow to the selected Project Track.

### 3. Define Interfaces

Identify:

* Inputs
* Outputs
* Data passed between components
* Important dependencies

### 4. Identify Risks

Record the most important technical uncertainties.

Examples:

* Data availability
* Model feasibility
* Integration difficulty
* Agent behaviour
* Simulation assumptions
* Performance constraints

---

## 45–55 min — Review

The team presents:

1. Selected User Story
2. Solution approach
3. Major components
4. Data/information flow
5. Important risks
6. Key technical decision

The reviewer should be able to understand the proposed solution without seeing implementation code.

---

## 55–60 min — Retrospective

Discuss:

* Was the design simple enough?
* Did we identify unnecessary components?
* What technical uncertainty remains?
* What could prevent implementation?
* What should change in Sprint 4?

Record one improvement.

---

## Sprint Deliverables

By the end of Sprint 3:

* [ ] Selected User Story
* [ ] Acceptance Criteria
* [ ] Solution Design
* [ ] Component list
* [ ] Data/information flow
* [ ] Key technical decision
* [ ] Important risks
* [ ] Sprint Review evidence
* [ ] One Retrospective improvement

---

## Definition of Done for Sprint 3

Sprint 3 is Done when the team can clearly answer:

> **What are we building, what are its major components, how do they interact, and how will we know that it works?**

### Sprint Principle

> **Design enough to build confidently — but do not design the entire future before building the present.**
