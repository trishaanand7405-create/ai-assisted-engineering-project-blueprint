# AI Use Guidelines

> **Use AI deliberately. Verify everything that matters. Own the result.**

AI tools are available to help the team work faster and explore better solutions.

They must be used as **engineering assistants**, not as substitutes for engineering judgement.

---

## 1. Use AI for Assistance

Good uses include:

* Brainstorming
* Research
* Requirements refinement
* Design exploration
* Code generation
* Debugging
* Test generation
* Documentation
* Data analysis
* Alternative solutions

Use AI where it provides genuine value.

---

## 2. Give AI Context

Good results require good context.

When appropriate, provide:

* The problem
* The goal
* Relevant requirements
* Existing code
* Expected behaviour
* Constraints
* Technology/version
* Error messages

Avoid vague prompts when precision matters.

---

## 3. Verify Before Using

Treat AI output as **unverified until reviewed**.

Check:

* Facts
* Code
* Dependencies
* Calculations
* Technical claims
* Security implications
* Data transformations
* Model behaviour

For important decisions, seek additional evidence.

---

## 4. Protect Information

Never provide AI tools with information that the team is not authorised to share.

Do not expose:

* Passwords
* API keys
* Access tokens
* Private credentials
* Confidential business information
* Personal data
* Sensitive customer information

Use synthetic or sample data whenever possible in the workshop.

---

## 5. Understand Before Accepting

Before using AI-generated code or technical content, ask:

> **Can someone on our team explain what this does and why we need it?**

If the answer is no:

**Do not accept it yet.**

---

## 6. Keep the Solution Lean

AI can generate enormous amounts of content very quickly.

Do not confuse volume with value.

Avoid:

* Unnecessary libraries
* Excessive abstraction
* Duplicate code
* Large generated files
* Unused features
* Over-engineered architecture

Apply:

> **Clean. Green. Lean.**

---

## 7. Test AI-Assisted Work

Anything important generated or modified with AI should be validated.

Use appropriate:

* Tests
* Reviews
* Demonstrations
* Data checks
* Error handling
* Acceptance Criteria

AI-generated output is not evidence of correctness.

---

## 8. Be Transparent

When useful, record significant AI-assisted decisions.

For example:

``
Decision:
Use library X for capability Y.

AI assistance:
Compared three implementation approaches.

Human validation:
Reviewed documentation and tested the selected approach.

Decision:
Team accepted option X.
```

The objective is not to document every prompt.

The objective is to preserve important engineering reasoning.

---

## 9. Human Accountability

The team remains responsible for:

* Product decisions
* Technical decisions
* Code
* Data
* Testing
* Security
* Deployment
* Product outcomes

AI cannot accept responsibility for a product.

---

## Golden Rule

> **Prompt freely. Think critically. Verify carefully. Build responsibly.**

The best AI-assisted engineering team is not the team that generates the most AI output.

It is the team that uses AI to produce **better engineering outcomes**.
