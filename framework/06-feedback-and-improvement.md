# Feedback and Improvement

> **Every product increment creates information. Every Sprint should create learning.**

The AI-Assisted Engineering Project Blueprint treats feedback as a core part of engineering rather than an activity performed only at the end of a project.

Teams continuously use evidence and feedback to decide what should happen next.

---

## 1. Sources of Feedback

Feedback can come from:

* Users
* Product Owner
* Sprint Reviews
* Testing
* Engineering observations
* Data and model results
* Deployment experience
* Team Retrospectives
* New requirements
* Unexpected behaviour

Not all feedback requires immediate action.

The team should evaluate its importance.

---

## 2. Feedback Loop

``
BUILD
  ↓
TEST
  ↓
REVIEW
  ↓
FEEDBACK
  ↓
LEARN
  ↓
PRIORITISE
  ↓
IMPROVE
  ↺
```

This loop operates throughout the product lifecycle.

---

## 3. Classify the Feedback

Useful categories include:

| Type            | Example                               |
| --------------- | ------------------------------------- |
| Bug             | Something does not work correctly     |
| Enhancement     | Existing capability can be improved   |
| New Feature     | New user capability is required       |
| Technical Debt  | Engineering quality needs improvement |
| Data Issue      | Data is incomplete or incorrect       |
| Performance     | System is too slow or inefficient     |
| User Experience | Product is difficult to use           |
| New Requirement | Business/user need has changed        |

Classification helps the team decide what to do next.

---

## 4. Prioritise

The team should consider:

* User value
* Business/product importance
* Risk
* Effort
* Technical impact
* Urgency

Not every request belongs in the next Sprint.

> **Feedback creates options. Prioritisation creates direction.**

---

## 5. Retrospective Learning

Retrospectives focus on the **way the team worked**.

The team should ask:

### What worked?

Identify practices worth continuing.

### What did not work?

Identify problems or friction.

### What will we change?

Select one or two practical improvements.

Avoid creating a long list of improvements that nobody will implement.

---

## 6. Continuous Improvement

Improvement should be small and measurable.

Examples:

* Improve Sprint planning.
* Integrate earlier.
* Add an important test.
* Simplify the architecture.
* Improve documentation.
* Reduce unnecessary computation.
* Improve AI-assisted development practices.
* Automate a repetitive task.

The next Sprint should provide an opportunity to apply the improvement.

---

## 7. Learning with AI

AI-assisted engineering introduces an additional feedback loop:

``
PROMPT
  ↓
AI OUTPUT
  ↓
ENGINEER REVIEW
  ↓
VALIDATION
  ↓
ACCEPT / MODIFY / REJECT
  ↓
LEARNING
```

Teams remain responsible for the correctness and suitability of the final result.

---

## Improvement Principle

> **Do not merely complete Sprints. Improve the way you complete them.**

A mature engineering team continuously improves:

**the product, the technology, the process and the way people collaborate.**
