# Sprint 4 — Implementation

> **Turn the agreed solution design into the first working product increment.**

Sprint 4 is where the team begins substantial implementation.

The objective is not to complete the entire product.

The objective is to produce a **small but working increment** that can be demonstrated and tested.

---

## Sprint Goal

> **Implement the highest-value capability identified during the previous Sprints.**

---

## Inputs

Bring forward:

* Sprint 3 Solution Design
* Selected User Story
* Acceptance Criteria
* Component/data flow
* Technical decisions
* Known risks

---

## 00–10 min — Plan

The team should:

* Confirm the Sprint Goal.
* Break the User Story into small implementation tasks.
* Assign responsibilities.
* Identify the minimum working increment.
* Confirm what will be demonstrated.

Avoid assigning six completely independent pieces of work.

> **The team owns the product increment collectively.**

---

## 10–45 min — Execute

Build the selected capability.

Depending on the Project Track, this may include:

### AI / ML / DS / DL

* Data preparation
* Feature processing
* Model training
* Model evaluation
* Prediction workflow

### Intelligent Data Pipeline

* Data acquisition
* Processing
* Transformation
* Analytics
* Dashboard/output

### Multi-Agentic Pipeline

* Agent definitions
* Agent workflow
* Coordination
* Tool integration
* Output generation

### Digital Twin

* State representation
* Events
* State transitions
* Simulation/model logic
* Visualisation

Use AI tools where useful, but review and validate generated output.

---

## 45–55 min — Review

Demonstrate the **actual working state**.

Show:

* What was implemented?
* What works?
* What does not work?
* What evidence exists?
* What remains unfinished?

Do not demonstrate slides instead of the product when a working increment is expected.

---

## 55–60 min — Retrospective

Discuss:

* What helped us build quickly?
* What blocked implementation?
* Did we integrate early enough?
* What technical problem should we address next?
* What should change in Sprint 5?

Record one improvement.

---

## Sprint Deliverables

By the end of Sprint 4:

* [ ] Working implementation increment
* [ ] Selected User Story partially or fully implemented
* [ ] Core components connected
* [ ] Initial test evidence
* [ ] Known limitations recorded
* [ ] Sprint Review demonstration
* [ ] One Retrospective improvement

---

## Definition of Done for Sprint 4

Sprint 4 is Done when:

> **A real part of the product works well enough to be executed, inspected and demonstrated.**

It does not need to be production-ready.

It must, however, be **real**.

### Sprint Principle

> **Build something small that works rather than something large that only exists on paper.**
