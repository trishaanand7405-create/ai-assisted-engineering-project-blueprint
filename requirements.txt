# ---------
# This is the GLOBAL requirements file.

#
# Design Principles
# -----------------
# - Keep the global dependency footprint small.
# - Prefer mature open-source tooling.
# - Avoid unnecessary runtime dependencies.
# - Avoid cloud-provider-specific packages globally.
# - Avoid paid-service SDKs globally.
# - Keep documentation tooling separate from application tooling.
# - Use version ranges rather than blindly copying `pip freeze`.
#

#
#   python -m venv .venv

# Git Bash / Windows:
#
#   source .venv/Scripts/activate
#
# Linux / macOS:
#
#   source .venv/bin/activate
#
# Installation:
#
#   python -m pip install --upgrade pip
#   pip install -r requirements.txt

# =============================================================================
# Dependency Management Policy
# =============================================================================
#
# 1. Every global dependency must have a repository-wide purpose.
# 2. Project-specific dependencies belong in that project's requirements file.
# 3. Experimental AI/ML libraries must not be added globally without
#    repository-wide justification.
# 4. Cloud SDKs must not be added globally.
# 5. Vendor-specific AI API SDKs must not be added globally.
# 6. Heavy dependencies should be avoided unless clearly justified.
# 7. New dependencies should be reviewed before being added.
# 8. Dependency upgrades should be validated through the repository workflow.
# 9. Security vulnerabilities should be reviewed during maintenance.
# 10. Do not use `pip freeze` output as the curated global requirements file.
#
# =============================================================================
# Project-Specific Dependencies
# =============================================================================
#
# Future project structure should keep dependencies local, for example:
#
#   projects/
#   ├── project-a/
#   │   └── requirements.txt
#   └── project-b/
#       └── requirements.txt
#
# This prevents unrelated projects from becoming coupled through global
# dependency management.
