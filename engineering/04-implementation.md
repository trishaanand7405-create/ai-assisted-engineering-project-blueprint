# Implementation

> **Implementation turns an agreed solution design into a working product increment.**

Implementation is not simply writing code.

The team converts the Product requirement and Solution Design into something that can be **executed, tested, demonstrated and improved**.

---

## 1. Start With the Sprint Goal

Before implementation:

* Confirm the Sprint Goal.
* Identify the selected User Stories.
* Review Acceptance Criteria.
* Review the Solution Design.
* Confirm what must be demonstrated.

The team should know **what outcome it is trying to achieve** before starting implementation.

---

## 2. Build Incrementally

Do not attempt to build the entire product at once.

Use a simple progression:

```text 
SMALLEST WORKING PIECE
          ↓
        TEST
          ↓
       INTEGRATE
          ↓
        EXTEND
          ↓
        TEST
          ↓
       DEMONSTRATE
```

A small working increment provides feedback much earlier than a large unfinished implementation.

---

## 3. Use Appropriate Engineering Practices

Depending on the project, implementation may include:

* Writing application code
* Preparing data
* Building processing pipelines
* Training models
* Creating APIs
* Developing dashboards
* Building agents
* Implementing simulations
* Integrating components
* Configuring existing tools

Use the simplest technology that can satisfy the requirement.

---

## 4. AI-Assisted Implementation

AI tools may be used to accelerate engineering work.

For example, AI can assist with:

* Code generation
* Refactoring
* Debugging
* Test generation
* Documentation
* Data transformation logic
* Algorithm exploration
* Explanation of unfamiliar code

However:

```text 
AI SUGGESTION
      ↓
ENGINEER REVIEW
      ↓
UNDERSTAND
      ↓
TEST
      ↓
ACCEPT / MODIFY / REJECT
```

> **Never treat generated code as trusted code simply because it runs.**

The team remains responsible for the final implementation.

---

## 5. Keep the Code Understandable

Prefer:

* Clear names
* Small functions
* Simple logic
* Appropriate comments
* Consistent structure
* Reusable components where useful
* Minimal dependencies

Avoid unnecessary abstraction.

> **Code should be understandable by another member of the team.**

---

## 6. Integrate Frequently

Do not allow each team member to build isolated pieces for too long.

Regularly:

* Combine changes.
* Run the application.
* Test component interactions.
* Resolve conflicts.
* Check existing functionality.

Integration problems become more expensive when discovered late.

---

## 7. Implementation Check

Before considering implementation ready for demonstration:

* [ ] The selected requirement is implemented.
* [ ] Acceptance Criteria are addressed.
* [ ] Components work together.
* [ ] The implementation has been tested.
* [ ] AI-generated code has been reviewed.
* [ ] Known limitations are understood.
* [ ] The team can explain the implementation.
* [ ] The work contributes to the Sprint Goal.

### Principle

> **Build small. Test early. Integrate often. Understand what you ship.**
