# Examples

> **Worked examples demonstrating how the AI-Assisted Engineering Project Blueprint can be applied in practice.**

This folder complements the conceptual guidance, processes, checklists and templates defined elsewhere in the blueprint.

The documents here use a single example product — the **Smart Campus Service Portal** — to demonstrate how the different parts of the blueprint connect across the engineering lifecycle.

---

## Purpose

The purpose of this folder is to answer a practical question:

> **What does the blueprint look like when its principles and practices are actually applied to a project?**

The examples are intentionally concrete.

They demonstrate:

* Project initiation
* Product definition
* User Story development
* Sprint planning
* Engineering decision-making
* Quality validation
* Deployment
* Incident management
* Retrospective learning

---

## Example Project

All examples use a common fictional product:

### Smart Campus Service Portal

The product provides students with a single place to:

* Discover campus services
* Understand service requirements
* Submit service requests
* Track requests
* Receive service updates

Service staff can:

* View requests
* Process requests
* Update request status
* Communicate with students

The example is deliberately small enough to understand while being sufficiently realistic to demonstrate the engineering lifecycle.

## Examples Are Illustrative

These documents are **not prescriptive project specifications**.

They are intended to demonstrate patterns.

A real project may have:

* Different users
* Different constraints
* Different architecture
* Different quality requirements
* Different release processes
* Different organisational structures

The examples should therefore be adapted rather than copied mechanically.

---

## AI-Assisted Work in the Examples

AI is deliberately included as part of several examples.

The examples demonstrate an important distinction:

```text
AI Assistance
     ↓
Candidate Output
     ↓
Human Review
     ↓
Evidence / Validation
     ↓
Engineering Decision
```

AI can accelerate engineering work, but it does not automatically establish correctness.

The responsible team remains accountable for:

* Product decisions
* Architecture
* Code
* Testing
* Security
* Release decisions
* Operational actions
