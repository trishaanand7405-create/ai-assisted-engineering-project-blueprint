# Track 01 — AI / ML / DS / DL Applications

> **Turn data into useful predictions, classifications, recommendations or insights that create measurable user value.**

This project track covers applications that use **Artificial Intelligence, Machine Learning, Data Science and/or Deep Learning** as an important part of the product.

The team must build an **end-to-end product**, not just a trained model.

---

## 1. Typical Product Flow

```text
PROBLEM
   ↓
DATA
   ↓
DATA PREPARATION
   ↓
EXPLORATION / ANALYSIS
   ↓
MODEL DEVELOPMENT
   ↓
MODEL EVALUATION
   ↓
INTEGRATION
   ↓
DEPLOYMENT
   ↓
PREDICTION / INSIGHT
   ↓
USER
```

The exact flow depends on the product.

---

## 2. Typical Components

A project may include:

* Data acquisition
* Data validation and preparation
* Exploratory analysis
* Feature engineering
* Model training
* Model evaluation
* Model persistence
* Application or API
* User interface or dashboard
* Prediction or recommendation workflow

The team should use **only the components that are actually required**.

---

## 3. Possible Applications

Examples include:

* Classification
* Regression
* Prediction
* Recommendation
* Anomaly detection
* Forecasting
* Image analysis
* Text analysis
* Pattern recognition
* Decision-support applications

The application should begin with a meaningful problem rather than a desire to use a particular algorithm.

---

## 4. Model Development

The team should be able to explain:

* What data was used?
* What problem is the model solving?
* Why was the selected approach considered appropriate?
* How was the data prepared?
* How was the model trained?
* How was it evaluated?
* What does the evaluation tell us?
* What are the known limitations?

> **A model is a component of the product — it is not the product itself.**

---

## 5. Product Integration

The trained model should eventually become part of a usable workflow.

For example:

```text
USER INPUT
    ↓
VALIDATION
    ↓
PREPROCESSING
    ↓
MODEL
    ↓
PREDICTION
    ↓
RESULT
    ↓
USER
```

The final product should allow someone to **use or demonstrate the capability**, rather than merely inspect a notebook or training script.

---

## 6. Minimum Demonstration

By the later Sprints, the team should be able to demonstrate:

* A defined problem
* A usable data source
* A reproducible preparation process
* A trained or selected model
* Evidence of model evaluation
* A working prediction/analysis workflow
* A simple usable interface, API or application
* Known limitations

Sophisticated infrastructure is **not required**.

---

## Track Principle

> **Data → Model → Product → Value**

Do not optimise for the most complicated model.

Optimise for a solution that is:

**Useful + Understandable + Testable + Demonstrable**

The engineering team is responsible for validating both the **model** and the **product outcome**.
