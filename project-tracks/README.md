# Project Tracks

> **Four different technology domains. One common engineering lifecycle.**

This folder defines the four project categories available within the AI-Assisted Engineering Project Blueprint.

The tracks allow teams to build different kinds of products while following the same fundamental **Product, Agile and Engineering disciplines**.

## The Four Tracks

### 1. AI / ML / DS / DL Applications

**[01 — AI / ML / DS / DL](01-ai-ml-ds-dl.md)**

Products where Artificial Intelligence, Machine Learning, Data Science or Deep Learning is a major part of the solution.

Typical flow:

```text
Data → Preparation → Model → Evaluation → Application → Prediction / Insight
```

---

### 2. Intelligent Data Pipelines

**[02 — Intelligent Data Pipelines](02-intelligent-data-pipelines.md)**

Products where the primary capability is acquiring, processing, analysing and delivering useful information.

Typical flow:

```text
Acquire → Validate → Process → Analyse → Serve → Visualise
```

---

### 3. Multi-Agentic Pipelines

**[03 — Multi-Agentic Pipelines](03-multi-agentic-pipelines.md)**

Products where specialised agents collaborate to accomplish a meaningful goal.

Typical flow:

```text
Request → Plan → Specialised Agents → Validate → Outcome
```

---

### 4. Digital Twins

**[04 — Digital Twins](04-digital-twins.md)**

Products that represent a physical, biological or conceptual system computationally and use state, events, models or simulation to generate useful insights.

Typical flow:

```text
Observe → Represent → Model → Simulate → Understand → Improve
```

---

## Common Foundation

The four tracks do **not** have separate methodologies.

Every team follows the same foundation:

```text
PRODUCT
  ↓
Problem → Users → Vision → Goals → Stories → Backlog
  ↓
AGILE
  ↓
Plan → Sprint → Build → Review → Retrospect
  ↓
ENGINEERING
  ↓
Understand → Design → Build → Test → Integrate → Demonstrate
  ↓
PROJECT TRACK
  ↓
AI/ML | DATA | AGENTS | DIGITAL TWIN
```

The **technology changes**.

The **engineering discipline remains consistent**.

---

## Track Selection

Teams should select or receive a track based on:

* Product problem
* User value
* Available data
* Team capability
* Available tools and environment
* Time available
* Demonstration feasibility

The objective is not to select the most technically impressive track.

> **Select a problem that the team can understand, build, test and demonstrate within the available time.**

---

## Track Principle

> **Different products. Different technologies. One disciplined way of working.**

All four tracks ultimately follow the same product lifecycle:

```text
VISION
  ↓
BACKLOG
  ↓
SPRINT
  ↓
WORKING INCREMENT
  ↓
DEMONSTRATION
  ↓
FEEDBACK
  ↓
IMPROVEMENT
  ↺
```

The purpose of the Project Tracks is to provide **technical context**, not to create four separate engineering worlds.
