# Problem Statement

> **Start with the problem. Do not start with the technology.**

A Product begins with a meaningful problem or opportunity.

Before selecting technologies, models, frameworks or architectures, the team must understand **what problem it is trying to solve and why solving it matters**.

---

## 1. Identify the Problem

Describe the problem clearly and specifically.

Ask:

* What is happening today?
* What is difficult, inefficient, expensive, slow or unreliable?
* Who experiences the problem?
* How frequently does it occur?
* What happens if the problem remains unsolved?

Avoid vague statements such as:

> "We want to build an AI application."

Instead describe the actual problem:

> "Users currently spend significant time manually analysing incoming data before making a decision."

---

## 2. Identify the Affected Users

Determine who experiences the problem or benefits from solving it.

Consider:

* Primary users
* Secondary users
* Operators
* Decision-makers
* Other stakeholders

The same product may serve multiple user groups with different needs.

---

## 3. Describe the Current Situation

Briefly document how the problem is currently handled.

Consider:

* Existing process
* Existing tools
* Manual activities
* Data sources
* Known limitations
* Current pain points

This establishes the **baseline** against which improvement can be evaluated.

---

## 4. Define the Desired Outcome

Describe what should become better if the problem is solved.

Examples:

* Reduce processing time
* Improve prediction accuracy
* Automate repetitive work
* Improve decision support
* Increase visibility
* Detect important events earlier
* Reduce errors
* Enable a new capability

Focus on **outcomes**, not implementation technology.

---

## 5. Define the Initial Scope

State what the team intends to address during this project.

Also identify what is **outside the initial scope**.

A realistic scope is essential for an Agile project.

> **A small, clearly defined problem is better than an enormous problem that cannot be demonstrated.**

---

# Problem Statement Template

The team should be able to complete the following:

```text
PROBLEM
What problem are we solving?

USERS
Who experiences this problem?

CURRENT SITUATION
How is the problem handled today?

PAIN / IMPACT
Why does the problem matter?

DESIRED OUTCOME
What should become better?

INITIAL SCOPE
What will our team address?

OUT OF SCOPE
What will we deliberately not address?
```

---

## Problem Statement Quality Check

Before moving forward, ask:

* [ ] Is the problem clearly stated?
* [ ] Are the affected users identifiable?
* [ ] Is the current situation understood?
* [ ] Is the impact meaningful?
* [ ] Is the desired outcome clear?
* [ ] Is the initial scope realistic?
* [ ] Have we avoided choosing technology prematurely?

### Principle

> **Problem First → User First → Value First → Technology Later**

A strong Problem Statement becomes the foundation for the **Product Vision, Product Goals, User Stories and Product Backlog**.
